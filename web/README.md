# Первый локальный клиент Gym — P03.1

Пользователь запросил начало реализации 2026-10-25. В этом срезе работает мобильный клиент с постоянным локальным хранением: выбрать шаблон, записать/исправить/удалить подход, завершить неполную тренировку, открыть её из истории и продолжить после перезагрузки без сети.

В P06 добавлены отдельное демо, вход через Яндекс ID, профиль с кэшем серверной программы и просмотр/одобрение конкретного черновика. Реальный вход требует [конфигурации окружения и приёмки](../infra/accounts-programs.md); без неё сервер отказывает, фиктивные аккаунты не создаются. Локальная очередь не пересылается и не показывается синхронизированной: это P07/P08. Демо не переносится в аккаунт автоматически. При локальном запуске явно выбери «Открыть демо».

## Запуск

Используй Node.js 24 (точная версия CI в [.node-version](.node-version)), npm и браузер. Из `web/`:

```sh
npm ci
npm run dev
```

Для проверки открытия без сети используй собранную версию:

```sh
npm run build
npm run preview
```

Открой <http://127.0.0.1:4173/> и дождись подписи «Можно открыть без сети». Начни тренировку, запиши подход, отключи сеть и перезагрузи страницу: занятие можно продолжить. `npm run dev` предназначен для разработки и не регистрирует service worker. Первый запуск без ранее загруженной сборки не поддерживается.

На текущей Windows-машине официальный переносимый Node 24.22.1 установлен в игнорируемый `.local/tools/`, его архив проверен по опубликованной SHA-256. В глобальный PATH он не добавлялся. Из корня репозитория можно пользоваться [обёрткой PowerShell](../scripts/web.ps1):

```powershell
& ./scripts/web.ps1 -Task build
& ./scripts/web.ps1 -Task preview
```

На новой машине установи Node 24 и выполни `-Task install` для зависимостей и тестового Chromium. Если политика Windows блокирует локальные сценарии и нет обязательной политики организации, используй `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` только для текущего процесса.

## Реализованное поведение

- Только упражнения выбранного шаблона; вес в кг, повторения и фактическое число подходов. Нет разовых замен, добавления упражнений, помощи/собственного веса, времени/расстояния.
- Снимок готовых целей копируется при старте. Приложение не рассчитывает прогрессию: цифры и шаги кнопок взяты из тестовой конфигурации, не являются персональной рекомендацией.
- Новый рабочий подход получает свою плановую цель; дополнительный — последнюю плановую цель. Разминка явно отделена и не занимает рабочий слот. После фактического повышения веса следующий подход снова получает план.
- Изменение полей ещё не означает запись. Несохранённый ввод сохраняется при переходе между экраном упражнения и обзором в открытом приложении; после перезапуска восстанавливаются только зафиксированные результаты.
- Объём и процент берутся из сохранённых плановых/фактических значений; отметка 100% видна, числовое превышение не обрезается. При нулевом плановом объёме процент не придумывается.
- Удаление и завершение подтверждаются явно. Завершённое занятие можно исправлять; пустое можно отменить. Удалённые факты помечаются, а их исходные действия остаются в локальной очереди.

Для первого среза выбраны React/TypeScript/Vite и IndexedDB; версии зависимостей закреплены в package-lock. Предварительные локальные правила: вес — конечное неотрицательное число, повторения — положительное безопасное целое; у владельца одна активная локальная тренировка. Первая свободная плановая позиция используется для новой записи; удаление не перепривязывает уже записанные подходы. Это внутренний контракт среза, который нужно сверить с P02.3 до серверной реализации. Он не является автоматически утверждённым REST/MCP-протоколом.

## Сохранность и границы

[repository.ts](src/repository.ts) записывает снимок/изменение занятия и исходящую операцию одной транзакцией IndexedDB. UI получает успех только после `transaction.oncomplete`. Ошибка добавления операции откатывает изменение факта; ввод остаётся для повтора. Стабильный ID операции устраняет повтор, другой payload под тем же ID отклоняется. Повтор прежнего действия возвращает текущее состояние, а не откатывает интерфейс к старому снимку.

Ревизия проверяется внутри той же транзакции. Две вкладки со старой ревизией не могут молча затереть друг друга: клиент показывает конфликт и предлагает явно обновить данные. Это пока консервативная блокировка всей тренировки, а не окончательное слияние устройств. «Обновить данные» сбрасывает несохранённую форму; сохранённые записи остаются.

Локальные записи/очередь разделены по `ownerId`. P06 получает владельца только из `/auth/session`; демо использует отдельный `local-demo`. При смене аккаунта прежний раздел сохраняется и требуется явно открыть другой профиль. Cookie имеет Secure/HttpOnly; CSRF хранится только в памяти, ответы входа не сохраняются в IndexedDB. Эта изоляция не шифрует профиль браузера и дополняет серверную авторизацию. Не переноси тестовые записи автоматически в настоящий аккаунт и не отправляй старую очередь от нового пользователя.

[build-shell.mjs](scripts/build-shell.mjs) формирует кэш точного набора ресурсов сборки. Service worker сохраняет только оболочку, никогда API/пользовательские ответы; API-маршруты исключены. Для явно перечисленных общедоступных ресурсов игнорируется `Vary` при чтении precache: заголовки загрузки модуля и первоначального заполнения кэша могут отличаться. Обновление не вызывает принудительного перезапуска страницы, не удаляет IndexedDB и не чистит старые кэши. Их контролируемое удержание/очистка ещё нужны перед пилотом.

Очередь имеет только статус `pending`, не отправляется и не очищается. Формат операций, совместимость/хранение, серверная идемпотентность и требования к миграциям локальной схемы описаны в принятом [проекте P02.3](../docs/workout-sync-design.md), но ещё не реализованы. Очистка данных браузера или смена origin может уничтожить/скрыть несинхронизированные записи; синхронизация/резервное восстановление в этом срезе отсутствуют. Не считай локальную историю резервной копией.

## Проверки

```sh
npm run lint
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

Либо из корня `& ./scripts/web.ps1 -Task check` после `-Task install`. Тесты не обращаются к облаку и используют только синтетические данные. На текущей машине браузерные тесты проверены также с уже установленным Chrome: `$env:PLAYWRIGHT_CHANNEL = 'chrome'`. Браузеры обёртки хранятся в `.local/playwright`.

Тесты модели/хранилища проверяют неизменность снимка, плановые позиции, разминку/дополнительные подходы, исправления, валидацию, атомарность, повторы, ревизии, разделение владельцев и конкурентный старт. Браузерные сценарии проверяют реальный IndexedDB, service worker и перезапуск без сети; отказ сохранения очереди; конфликт вкладок; ввод кнопками, сохранение формы при навигации и повторное событие отправки. Каждый сценарий выполняется на узком и широком экране Chromium.

[Web checks](../.github/workflows/ci.yml) выполняет форматирование, типизацию/сборку, модульные и браузерные тесты на PR/main без OIDC, секретов или доступа к общему staging. До публикации ветки процесс на GitHub не запускался. Реальные iPhone/Safari и Android ещё не проверены; эмуляция размеров Chromium их не заменяет.
