# Клиент Gym

Мобильная PWA на React/TypeScript/Vite: Яндекс ID, аккаунтные программы, запись подходов без сети, надёжная исходящая очередь и явный разбор конфликтов. Точный установленный выпуск и ограничения выкатки смотри в [журнале](../docs/development-log.md); локальная сборка не означает публикацию на staging.

## Использование

- Личный старт использует сохранённый серверный план. Без сети можно начать по такому кэшу, продолжить, исправить и завершить занятие; цели начатой тренировки не меняются после публикации новой программы.
- Вес вводится в кг, до трёх знаков после запятой, от 0 до 2000; повторения от 1 до 1000. Кнопки веса считают целые граммы. Разминка и дополнительные подходы имеют отдельные связи с планом; индикатор сохраняет отметку 100% и числовое превышение.
- Результат и действие сохраняются одной транзакцией IndexedDB. Успех показан после commit; при отказе запись не добавляется, ввод остаётся. Незаписанный ввод сохраняется при навигации внутри открытого приложения, но не считается надёжно сохранённым результатом.
- Открытие, foreground/online и кнопка «Синхронизировать» запускают проверку владельца, получение изменений и доставку. Повтор после обрыва сохраняет ID/тело, сначала проверяется квитанция. Background Sync не нужен. Счётчик локальных записей отделён от доставки на сервер.
- При конфликте сравни серверный и локальный результаты и предпросмотр всей непринятой цепочки. Выбор архивирует старые намерения и создаёт новые ID только после подтверждения; нового конкурентного конфликта это не скрывает.
- Выход/скрытие/смена аккаунта останавливают отправку и сохраняют отдельный профиль. Cookie/CSRF не попадают в IndexedDB/экспорт. Нет связи с сервером — это не автоматический выход. Демо и старые записи без серверного снимка не переносятся в облако автоматически.
- «Скачать локальную копию» выгружает личные занятия/очередь/архив решений в JSON. Автоматического импорта пока нет; храни файл как личные данные.

Схема stores, восстановление, состояния очереди и точные границы — в [регламенте P08](../docs/pwa-sync-implementation.md). Браузерный профиль не зашифрован приложением. Очистка данных браузера/смена origin может уничтожить или скрыть недоставленные факты; кэш не заменяет резервирование.

## Обновление

Service worker кэширует только точные публичные ресурсы оболочки, исключая auth/API/OAuth/MCP. «Обновить приложение» появляется при waiting: сначала запиши или явно сбрось ввод, закрой другие окна Gym, затем нажми кнопку. Автоматического reload/очистки IndexedDB нет, сохранённые занятия и очередь переживают переход.

При первом переходе со старого P07-клиента этой кнопки ещё нет: сохрани ввод и один раз закрой все вкладки/окна Gym, затем открой снова. Выходить из аккаунта или очищать данные сайта не нужно. При блокировке upgrade IndexedDB закрой старую вкладку; не удаляй БД.

## Разработка и проверки

Нужны Node.js 24 и Python 3.12 с [db/requirements.txt](../db/requirements.txt). Из web/:

```sh
npm ci
python -m pip install -r ../db/requirements.txt
npx playwright install chromium webkit
npm run lint
npm run build
npm test
npm run test:e2e
```

Для уже установленного Chrome задай PLAYWRIGHT_CHANNEL=chrome; тогда для локальной проверки нужен только отдельный WebKit. GYM_TEST_PYTHON позволяет указать интерпретатор с backend-зависимостями. Обёртка из корня `& ./scripts/web.ps1 -Task install` использует установленный Chrome, если он найден, и общий `.local/playwright` для остальных движков. `-Task check` ничего не устанавливает; проверяет lint/build/unit/browser и использует `.local/backend-venv`, если он существует. Python-зависимости установи один раз в это окружение.

Браузерный процесс сам запускает preview и синтетический HTTP API на localhost:4173/4174, оба порта должны быть свободны. Тестовый прокси включён только переменной GYM_E2E_API при запуске тестового preview. Контрольные endpoints/выбор синтетической сессии находятся только в tests/api-server.py и не входят в runtime Gym или dist. Браузерные запросы доходят до настоящего api.handler/прикладных сервисов на временной SQLite; бизнес-логика API не дублируется в JS.

Проекты: mobile-chromium, desktop-chromium, mobile-webkit (iPhone viewport). Сценарии охватывают IndexedDB/service worker, сохранение без сети и перезапуск, обрыв после серверного исполнения, второе устройство, оба выбора всей конфликтующей цепочки, отказ сохранения и управляемый переход уже установленной PWA. Native YDB-транзакции проверяет отдельный CI job. Физические iPhone/Android, домашний экран и вытеснение хранилища ещё требуют smoke перед пилотом; эмуляция их полностью не заменяет.

[Web checks](../.github/workflows/ci.yml) запускается без облачных секретов/OIDC/доступа к общему staging. Browser job выполняется при изменениях web/ или CI, использует закреплённый официальный Playwright-образ с уже установленными движками. Повторной загрузки Chrome в каждом CI нет.
