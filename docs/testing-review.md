## Профили

| Изменение | Обязательная проверка |
| --- | --- |
| Известный компонент отображения, CSS, изображения | Lint, TypeScript/сборка, быстрые unit, контрактные векторы; два сквозных сценария в Chromium |
| Остальной клиент, IndexedDB, очередь, сессии, service worker | Проверки web и полная браузерная матрица |
| API, YDB, общие контракты | Контракты, сервер, одноразовая YDB, упаковка/выпуск, web и полная браузерная матрица |
| Инфраструктура и публикация | Изолированные тесты инфраструктуры, сборки и выпуска |
| Только документация/скиллы | Ссылки и diff; прикладной CI и публикация не запускаются |
| Неизвестная область, workflows, выбор проверок | Полный набор |

`App.tsx` управляет синхронизацией и хранилищем, поэтому относится к интеграционному профилю. Кнопка завершения упражнения вынесена в чистый компонент отображения. Не расширяй список лёгких компонентов без проверки их зависимостей.

Быстрый профиль содержит два существующих сценария: запись/исправление/история без сети и ввод/разминка/защита от повторной отправки. Они работают без Python API и установки браузера: используется установленный Chrome, доступный и на [GitHub Ubuntu runner](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md). Локально два сценария прошли за 4,2 секунды; это не замер всего CI.

Полная матрица сокращена с 57 до 40 запусков: все 19 сценариев остаются в мобильных Chromium и WebKit, на desktop Chromium остаются два smoke-сценария. Исключены 17 повторов desktop, а не проверки надёжности. Авторизация, изоляция аккаунтов, офлайн-очередь, конфликты, миграции, идемпотентность и исправления истории сохранены. Быстрые 59 unit-тестов не удаляются: локально собственно проверки занимают доли секунды. Полная матрица прошла локально за 38,1 секунды.

Полный набор запускается также каждую ночь и вручную. Итоговое задание `checks` требует успешного завершения всех выбранных заданий; пропущенный обязательный тест не считается успехом. План проверок привязан к SHA и передаётся из успешного push CI в release gate: документация и тесты не пересобирают приложение. Диапазон push целиком учитывает несколько коммитов, а не только `HEAD^`.

## Локально и после merge

Выбери профиль: `python scripts/check_scope.py detect --base origin/main --worktree`. Для web используй `scripts/web.ps1 -Task check`; принудительный полный профиль — `-Task check-full`. После изменения инфраструктуры выбирай соответствующие Python-наборы. Не повторяй уже успешные проверки без новых правок или конкретной причины.

После merge прикладного изменения выполни `python -m infra.delivery_status --sha <merge-SHA> --wait`. Команда ограниченно ждёт main CI/staging, останавливается при сбое и один раз сверяет `/__gym/release` с SHA/run/attempt. Она не читает БД и облачные секреты. Если `deploy=false`, ждать нового приложения не нужно.

Успешный deploy уже проверяет артефакты, Gateway/API, приватность и auth smoke. После совпадения публичного release ID сразу дай итоговую сводку. Повторная полная сверка облака или новый браузерный сценарий нужны при сбое, изменении механизма выпуска или отдельном требовании приёмки. В журнал достаточно записать PR/SHA, CI/staging run, release ID и результат; не создавай отдельный скрипт отчёта для каждой кнопки.

## Оставшееся ограничение

Публикация пока собирает весь неизменяемый выпуск, включая API и образ мигратора, даже для UI. В исходном замере это ещё примерно шесть минут. Повторное использование backend для выпуска только фронта потребует отдельного решения о происхождении артефактов, квитанциях миграций и ротации тегов; здесь это не реализовано. Нельзя обещать двухминутный полный цикл на основании быстрого браузерного smoke.
