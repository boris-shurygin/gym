# История, графики и тренировочный агент

## Страницы и показатели

Лендинг — [корень staging](https://gym-staging.website.yandexcloud.net/), PWA — [/#/app](https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net/#/app), одобрение — `/#/program?change_id=…`. Origin, manifest id/scope и базы тренировок сохраняются. Публичная страница не загружает личные отчёты без подтверждённой сессии. Переход из приложения со страницы с незаписанным вводом требует подтверждения.

В PWA: «История» → «Серверная история и графики». Обычные карточки показывают записи устройства, серверный раздел — отдельные снимки с редакцией и состоянием. Выбери 7/30/90 дней и часовой пояс IANA; можно подставить пояс браузера и явно сохранить. До выбора сервер использует UTC.

Графики используют существующие API summary/series и одинаковые с MCP определения: занятия по дням, рабочие подходы/повторения, максимальный рабочий вес с повторениями, объём упражнения. Разные упражнения/оборудование/весовые соглашения не объединяются; разминка исключена. Точные значения доступны рядом с графиком.

Кэш отчётов — отдельная `gym-statistics-v1`, максимум 40 записей на владельца. Ключ учитывает владельца, запрос/серию/период/пояс, версию расчёта, ревизию и календарные границы. После сети/ручного обновления загружается свежий отчёт; без сети показывается сохранённый с отметкой устаревания. Локальная очередь не прибавляется к серверной сводке. Серия читается до конца пагинации; смешанные ревизии отклоняются. `X-Gym-Expected-Owner` защищает отчёты при смене cookie-аккаунта.

## Python-клиент и скилл

Основной путь изменён по запросу пользователя, [ADR-0021](adr/0021-python-training-agent-client.md): агент вызывает локальный Python, настройки ChatGPT не нужны. Из корня репозитория:

```powershell
& ./.local/backend-venv/Scripts/python.exe -m gym_agent status
& ./.local/backend-venv/Scripts/python.exe -m gym_agent login
& ./.local/backend-venv/Scripts/python.exe -m gym_agent tools
& ./.local/backend-venv/Scripts/python.exe -m gym_agent call get_program
& ./.local/backend-venv/Scripts/python.exe -m gym_agent call get_training_summary --input .local/training/summary.json
```

Альтернатива — `scripts/gym-agent.ps1`. `login` открывает браузер и ждёт явного разрешения «Python-агент Gym» до пяти минут. Callback принимает code только на `127.0.0.1:8765`, проверяет state/issuer, а сервер проверяет PKCE. Токены сохраняются через Windows DPAPI текущего пользователя в игнорируемой `.local/agent-credentials/staging.dat`; plaintext fallback отсутствует. Refresh выполняется под файловой блокировкой. CLI работает только со staging; production и иное ОС-хранилище сюда не входят.

`call` принимает JSON-файл или `--input -` для stdin; веса — целые граммы. Ответ — `{ok,data}` либо ошибка, для черновиков есть `review_url`, для опубликованного изменения своего grant — `publication`. Личные временные payload-файлы держи в `.local/training/`. Содержимое хранилища токенов не выводи. После неопределённого результата записи повторяй только те же request_id/содержание.

Полный [Skill тренера](../skills/gym-trainer/SKILL.md) и [точка обнаружения для агента](../.agents/skills/gym-trainer/SKILL.md) отделены от скиллов разработки. Агент читает инструменты и вызывает Python; прямых SQL/YC-записей нет. Публикация требует кнопки Gym. Реальный приёмочный клиент P10 — Python; настройка ChatGPT больше не является блокирующей проверкой. Из физических устройств у пользователя доступен iPhone; реальный Android пока не подтверждён.

## Необязательный ChatGPT-коннектор

В настройках ChatGPT добавь собственный MCP-сервер с OAuth, если это доступно твоему аккаунту/рабочему пространству:

| Поле | Staging |
| --- | --- |
| MCP URL / resource | `https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net/mcp` |
| OAuth Client ID | `gym-chatgpt` |
| Client secret | Не требуется: публичный клиент, `none`, PKCE S256 |
| Разрешённый callback | `https://chatgpt.com/connector_platform_oauth_redirect` |
| Scopes | `program:read history:read stats:read program:draft program:publish` |

Сервер объявляет issuer identification и возвращает `iss`. Стабильный callback и публичный метод `none` сверены с [OpenAI Docs](https://developers.openai.com/plugins/build/auth). Если управление подключением показывает другой точный callback, обнови проверенный allowlist по фактической настройке; wildcard и открытая DCR не включены. Реальная доступность чтения/записи выбранному аккаунту ChatGPT — отдельная приёмка.

Войди через Яндекс ID и разреши показанные права на странице Gym. Попроси ChatGPT прочитать программу/историю, предложить и проверить небольшой черновик. Перейди по полученной ссылке Gym и нажми «Одобрить и опубликовать». Кнопка атомарно публикует точную редакцию; может понадобиться повторный Яндекс-вход. Ссылка на черновик сохраняется. Согласие в чате и OAuth-согласие не заменяют эту кнопку.

`get_program_change` затем показывает опубликованное состояние, а в тексте MCP своего grant — результат публикации. `apply_program_changes` подтверждает этот результат с точными approval_id/base/digest/revision; он не создаёт одобрение. Отзыв подключения доступен на лендинге в разделе «Доступ тренировочного агента» и немедленно блокирует access/refresh grant. Выход из PWA — отдельное действие.

Отдельный [Skill тренера](../skills/gym-trainer/SKILL.md) готов как инструкции выбранного клиента; автоматически в ChatGPT он не устанавливается. Это не `.agents/skills/` разработки. Не присылай в чат OAuth code/state, tokens, cookies, секреты или полный callback URL.

## Реализация и границы

`api/mcp.py` реализует stateless Streamable HTTP с JSON-ответами и согласованием версий 2025-03-26/2025-06-18/2025-11-25. GET/SSE, server-initiated requests, DCR и CIMD не заявлены. Все 11 инструментов берутся из принятых контрактов, вызывают Programs/Workouts/Analytics и повторно проверяют token/scope внутри транзакции. Метаданные OAuth публичны; инструменты требуют Gym Bearer, cookie PWA и токены Яндекса/CI не подходят.

`api/delegation.py` хранит хеши access/refresh и одноразовых кодов в существующих sessions/login_transactions, grant — в program_records. Access: 10 минут; refresh: 30 дней бездействия/90 дней максимум; повтор использованного refresh атомарно отзывает семейство. Владелец, клиент, resource, scopes, disabled-account и отзыв проверяются для каждой операции. Новые таблицы, миграции, IAM и секрет клиента не нужны. Истёкшие записи пока сохраняются; регулярная очистка, дополнительные лимиты и наблюдаемость относятся к P11.

## Реальные устройства

Лендинг предлагает браузерный prompt установки и ручной путь. Инструкции сверены с [Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios) и [Chrome Android](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en); названия меню зависят от версии. После установки открой Gym с иконки, дождись загрузки, отключи сеть, запиши подход и перезапусти приложение; после возврата сети проверь доставку. Установка на физических iPhone/Android и настоящий ChatGPT отмечаются отдельно в журнале; эмуляция не считается их заменой.
