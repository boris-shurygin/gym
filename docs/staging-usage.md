# Как открыть актуальный staging

Читаемая ссылка: [Gym staging](https://gym-staging.website.yandexcloud.net/). Она перенаправляет на [постоянный адрес Gateway](https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net/). Смена выпуска меняет версии API/PWA, а не адрес шлюза.

## Старая оболочка и логин

Если видны «Твой аккаунт» без логина и «Облачная синхронизация ещё не подключена», браузер использует прежний shell. Новая оболочка показывает `yandex_login`, полученный сервером от Яндекса. Прежняя сессия может быть действующей, но ещё не содержать этой подписи.

Открой [страницу обновления](https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net/auth/update-app). Она находится под `/auth/`, поэтому прежние service worker пропускают её в сеть. Точный маршрут Gateway отдаёт публичный `update.html`; остальные auth-маршруты остаются API.

Сохрани незаписанный ввод и закрой остальные окна Gym. Кнопка «Обновить и подтвердить аккаунт» активирует готовый новый worker и начинает обычный вход через Яндекс. Cookies, кэши и IndexedDB не очищаются. Другие открытые окна блокируют принудительную активацию. Переход выполняется только после нажатия; существующие тренировки и очередь сохраняются. Токены/параметры callback никому передавать не нужно.

## Два тестовых шаблона

В пустом аккаунте staging появляются «Тестовая A — верх тела» и «Тестовая B — низ тела»: по три упражнения, три подхода по восемь повторений. Условные плановые веса показаны до публикации; это данные для проверки интерфейса. Фактические значения пользователь вводит сам.

Кнопка «Добавить тестовую программу» через текущую сессию создаёт предложение, проверяет его и явно публикует два шаблона существующими API. `expected_owner_id`, исходная пустая версия и digest проверяются сервером. Готовая программа не заменяется; истории тренировок не переписываются. Request ID сохраняются отдельно для владельца, поэтому повтор после потерянного ответа безопасен. После успеха программа хранится в YDB и загружается как обычная опубликованная программа, а не как локальное демо.

Панель показывается только при серверном `purpose=staging-release`, действующей сессии и отсутствии программы. Прав доступа, административных сессий и обходов одобрения не добавляется. Оператор не создаёт пользовательскую сессию ради заполнения реального аккаунта.

## Человекочитаемый адрес

У Object Storage есть читаемый адрес по имени бакета: `https://<имя-бакета>.website.yandexcloud.net/` ([документация](https://yandex.cloud/ru/docs/storage/concepts/hosting)). Проверено 2026-10-30: бакет `sportstats` находится в default-каталоге `b1ge1i2ulr0hkqp4fn6p`, настроен на `index.html`, разрешает публичное чтение объектов, а его HTTPS-сайт отвечает 200. Настройки и содержимое `sportstats` не менялись.

Для Gym создана отдельная читаемая точка входа `https://gym-staging.website.yandexcloud.net/` ([конфигурация и обслуживание](../infra/staging-redirect.md)). Этот адрес относится к статическому хостингу Object Storage. API Gateway выдаёт служебный домен с ID; для своего адреса непосредственно на Gateway требуется [подключение собственного домена](https://yandex.cloud/ru/docs/api-gateway/operations/api-gw-domains). Прежний вывод о необходимости своего домена был слишком широким: он не учитывал адрес сайта Object Storage.

Пустой бакет с переадресацией всех запросов возвращает 301 на нынешний HTTPS-origin, сохраняя путь. После редиректа в адресной строке останется домен Gateway; приложение продолжит использовать существующие cookies, IndexedDB, очереди и callback Яндекса. Публичный доступ к объектам/списку/конфигурации бакета закрыт. Перенос самого приложения на новый origin — отдельное действие: требуется согласованный перенос локальных данных, изменение OAuth callback и серверной проверки Origin. Не меняй origin действующей PWA одним добавлением CNAME.
