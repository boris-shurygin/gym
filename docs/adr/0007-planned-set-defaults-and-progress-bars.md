# ADR-0007: Плановые значения по умолчанию и индикаторы выполнения

- **Статус:** Заменён решением [ADR-0008](0008-set-volume-progress-bars.md)
- **Примечание:** ADR-0008 сохраняет плановые значения ввода по умолчанию и отдельный индикатор числа подходов, но заменяет индикаторы только по повторениям на индикаторы объёма в кг × повторения. Эта запись сохранена для исторического контекста.
- **Дата:** 2026-10-18

## Контекст

На отдельном экране упражнения пользователи записывают несколько подходов и часто выполняют меньше или больше повторений, чем предписано. Наследование предыдущего **фактического** результата может переносить отклонения в следующую запись. Пользователь хочет сохранять видимость ожиданий программы и просит визуальные полосы выполнения, явно показывающие недобор и превышение.

## Решение

- Каждая новая запись рабочего подхода начинается с **планового веса и рекомендуемого числа повторений** независимо от предыдущего фактического подхода. Цели могут различаться между плановыми подходами.
- Редактируемые значения — фактический ввод, а не правки опубликованной программы или зафиксированного плана занятия.
- Для рабочих подходов сверх предписанного количества использовать цель последнего планового рабочего подхода как явно обозначенную основу сравнения/предзаполнения.
- Показывать **индикатор выполнения каждого подхода** по фактическим повторениям относительно предписанных/рекомендуемых: с видимой отметкой 100%, недобором до цели и **выходом за 100% при превышении**, числовыми подписями факта/плана и разницей.
- Показывать **отдельное число рабочих подходов** относительно предписанного, также различая невыполненные и дополнительные подходы. Разминка не засчитывается в выполненные рабочие подходы.
- Если фактический вес отличается от плана, отдельно отмечать отклонение веса; **не** трактовать более высокое отношение повторений при меньшем весе как общее перевыполнение.
- Сервер должен предоставлять явное рекомендуемое число повторений для каждого планового подхода, даже если правило задаёт диапазон; мобильный клиент не должен угадывать конкретное значение из диапазона.

## Последствия

- Экран записи не наследует предыдущий фактический результат как следующее значение по умолчанию, снижая риск случайного переноса недостигнутой цели.
- Отклонение повторений каждого подхода и общее выполнение рабочих подходов видны без смешивания этих двух измерений.
- Данные плана/снимка требуют целей для каждого подхода или их детерминированного определения. Дополнительные подходы могут использовать опорную цель, оставаясь фактически дополнительными.
- Фактическое выполнение и решения прогрессии остаются раздельными: сервер использует исходные данные и критерии правил, а не визуальные проценты.
- Цвет — не единственный индикатор: числовые цели/разницы и подписи обеспечивают доступность.

## Отложенные подробности интерфейса

Форма/масштаб индикатора и ограничение отображаемого превышения, точные элементы числового ввода и любой суммарный показатель объёма/повторений требуют UX-тестирования. Решение использовать плановые значения по умолчанию и видимые индикаторы недобора/превышения принято.
