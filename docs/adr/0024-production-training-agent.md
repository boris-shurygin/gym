# ADR-0024: Подключение тренировочного агента к production

Статус: Принят по прямому запросу пользователя «Давай подключимся к проду» 2026-11-01.

## Контекст

[ADR-0021](0021-python-training-agent-client.md) выбрал локальный Python-клиент и ограничил первый выпуск staging и Windows DPAPI. Пользователь запросил подготовку содержательной личной программы в production и подключение агента к своему production-аккаунту. Текущее рабочее окружение — Linux с Secret Service. Для этой задачи нужен отдельный пользовательский вход в production; перенос staging-токенов и операторская запись в YDB не подходят.

## Решение

Клиент `python -m gym_agent` поддерживает явный параметр `--environment production`; без параметра сохраняется staging. Адреса окружений закреплены в клиенте:

| Окружение | Origin |
| --- | --- |
| `staging` | `https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net` |
| `production` | `https://d5dhqvda3eo6r4c2mgf6.764nr5vy.apigw.yandexcloud.net` |

Произвольный origin через CLI не настраивается. Для каждой production-команды указывай `--environment production` явно. Используй прежний зарегистрированный клиент `gym-python`, PKCE S256 и точный callback `http://127.0.0.1:8765/callback`. Пользователь отдельно разрешает доступ к production-аккаунту через браузер; grant и учётные данные разделены по окружениям. Не переноси staging-токены в production.

На Windows сохраняй прежний DPAPI текущего пользователя, с отдельными `.local/agent-credentials/staging.dat` и `production.dat` в рабочей копии. На Linux используй Secret Service напрямую через `secretstorage` с зашифрованной D-Bus-сессией; изолируй записи по окружению и рабочей копии, включив в атрибуты хеш её канонического пути. Данные программы и текущего владельца в атрибуты не включай: владельца проверяет MCP. Требуй существующую разблокированную коллекцию; при недоступности хранилища заверши команду с ошибкой. Не создавай plaintext fallback, не проси секреты в чате и не извлекай токены вручную. На Linux сериализуй обновление токенов через `fcntl.flock`; файловые блокировки в обеих ОС разделяй по окружениям и храни в той же рабочей копии. Так два checkout не используют общие токены с независимыми блокировками. Не запускай параллельные `login`, поскольку callback-порт общий.

Серверные проверки владельца, scopes и отзыва сохраняются. Вход не публикует программу: подготовь и проверь черновик через прикладные MCP-инструменты, затем дождись кнопки «Одобрить и опубликовать» в Gym. Личные файлы программы и истории держи только в игнорируемой `.local/training/`.

## Границы и проверка

Решение заменяет только ограничения staging/Windows в ADR-0021. Серверный deploy, изменение прав, миграции и прямые SQL/YC-записи не нужны и этим решением не разрешаются.

Публичные OAuth-метаданные production и наличие разблокированного Linux-хранилища подтверждены при подготовке подключения. Это не подтверждает пользовательский вход. Считай подключение выполненным после отдельного OAuth-согласия пользователя, успешного `status` и чтения `get_program` с явным `--environment production`; фактический результат зафиксируй в журнале разработки.
