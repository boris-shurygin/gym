# ADR-0018: Ротация тегов функций

- **Статус:** Принят по запросу пользователя 2026-10-30
- **Дополняет:** [ADR-0013](0013-release-artifacts-and-migration-worker.md), пункт 7

## Причина

Лимит десяти тегов Functions остановил выкатку P08. Пользователь предложил сохранять возможность возврата на одну, максимум две предыдущие версии и автоматически освобождать остальные теги в staging и production.

## Решение

В каждом окружении сохраняй текущую и две предыдущие **различные успешные установки**. Учитывай порядок установки, включая откаты, а не время создания версии функции. Храни окно в метках ресурса функции `gym-tag-schema`, `gym-tag-current`, `gym-tag-previous-1/2`; сохраняй остальные метки.

До создания кандидата снимай остальные управляемые теги `r-*`. Защищай также кандидата и фактическую цель Gateway, даже если smoke после переключения не завершился. После smoke и сохранения неизменяемой квитанции обновляй окно и повторяй очистку. Неудачный кандидат не вытесняет успешного предшественника. При неизвестном состоянии остановись до удаления.

Пакеты, манифесты, образы, квитанции и ресурсы PWA сохраняются по прежнему правилу не менее 90 дней. Снятие тега разрешает YC позднее автоматически удалить старую версию функции: долговечность её ID за пределами окна больше не обещается. Это уточнение прежнего требования сохранности ресурсов ADR-0013. Самостоятельно версии, данные, старые API-контракты и форматы очереди не удаляй.

Для отката по-прежнему нужна совместимость с текущей схемой; хранение тега само по себе её не доказывает. Старый выпуск вне окна восстанавливай отдельным проверенным выпуском из архива, с новой идентичностью и квитанцией. Production остаётся за явным разрешением и защищённым Environment.

## Последствия

Обычное состояние — три тега выпуска; во время deploy может временно появиться четвёртый. Новых ролей, бакетов и секретов нет. Посторонние теги не удаляются; если они заняли квоту, процесс сообщает об этом до создания кандидата.

Все изменения окружения сериализованы существующим workflow; ручное параллельное редактирование Gateway/меток запрещено. У нескольких ресурсов YC нет общей транзакции: контрольные чтения обнаруживают расхождение, но не заменяют эту блокировку.

Переход со старой истории и действия при сбое описаны в [регламенте](../../infra/function-tag-retention.md).
