# ADR-0025: Измерения упражнений, стороны и группы подходов

- **Статус:** Принят к реализации и проверке на staging 2026-11-02; выпуск в production и личное наполнение — после проверки пользователем
- **Дата:** 2026-11-01
- **Обновлено:** 2026-11-02
- **Связано:** ADR-0005, ADR-0008, ADR-0015, ADR-0016, ADR-0017, ADR-0019

## Контекст

Пользователь запросил собственный вес, миоповторения, вес одной из нескольких
гантелей и односторонние упражнения. Планки требуют измерения времени; тренажёр
с неизвестными единицами требует сохранения показания шкалы без догадки о кг/фунтах.
Личный список нагрузок хранится отдельно в игнорируемой `.local/training/`.

Текущая v1 требует вес в граммах и повторения для каждой цели и результата.
`per_implement_kg` уже означает вес одного снаряда, но не содержит их количества.
Сервер считает `weight_g × reps`; число сторон и структура миоповторений отсутствуют.
Закрытые схемы не разрешают добавлять новые поля/типы незаметно для старого клиента.

Этот документ расширяет ограничения MVP новой версией контрактов. Старые
документы, операции и расчёты сохраняют свою семантику.

## Подтверждено пользователем

2026-11-02 пользователь подтвердил назначения односторонних упражнений на каждую
сторону и раздельное сохранение фактов левой/правой. Сначала работа ограничивалась
моделью и макетом.
Уточнения личного оборудования и назначений сохранены в локальном черновике.

После просмотра первого макета пользователь потребовал встроить вариации в
основной способ записи: сохранить добавление подходов и разминку. Отдельный
интерфейс выбора фиксированных плановых слотов не подходит. Основа — текущий
экран упражнения из `web/src/App.tsx` и правила ADR-0019.

Затем пользователь уточнил миоповторения: после активации достаточно предлагать
малое число повторений в следующих подходах той же формы. Отдельная кнопка
мини-подходов исключена. Число повторений и вес каждого подхода берутся из
назначения; личные значения сохраняются только в локальном макете.

Затем пользователь разрешил код, коммит, PR, merge и staging. Следующая граница —
его визуальная проверка; production и создание личных шаблонов выполняются позже.
Ни merge, ни техническая готовность клиента не заменяют одобрение публикации
личной программы в Gym.

## Модель

Раздели измерение результата, нагрузку и способ выполнения:

| Свойство | Представление |
| --- | --- |
| Результат | Повторения либо длительность в целых секундах |
| Собственный вес | Явный признак; масса тела не подставляется и не вычисляется |
| Известный внешний вес | Вес и соглашение о вводе: всего либо на один снаряд; при втором варианте — число одновременно используемых снарядов |
| Неизвестная шкала | Показание конкретного тренажёра с явно неизвестной единицей; не граммы и не предполагаемые фунты |
| Стороны | Обычное выполнение либо назначение каждой стороне; факты левой и правой записываются независимо |
| Структура | Обычные подходы либо группа миоповторений: активационный подход, упорядоченные мини-подходы, заданная подсказка отдыха |
| Назначение записи | Рабочая либо разминочная; независимо от единиц измерения, нагрузки и стороны |

Для тела без отягощения покажи «Свой вес» и поле повторений. Для планки покажи
длительность; ввод `мм:сс` преобразуй в секунды точно. Не представляй время
повторениями или фиктивным весом. Дополнительное отягощение к собственному весу,
помощь тренажёра и расстояние не включай в реализацию автоматически.

Число снарядов независимо от сторон. Две гантели, удерживаемые одновременно,
дают множитель нагрузки 2. Одна гантель с последовательным выполнением каждой
рукой даёт множитель 1 в каждом отдельном результате. Сохранение левой стороны
не создаёт факт правой; явное копирование может лишь предзаполнить её ввод.

Согласованный принцип — отдельные факты сторон. В интерфейсе: компактный
переключатель Л/П внутри существующей формы нового подхода. Сохраняй каждую
отдельно той же кнопкой «Записать подход». Счётчик показывает выполненные стороны и полностью
выполненные пары; шесть записей сторон не выдаются за шесть обычных подходов.
Равные цели обеих сторон не мешают сохранять разные факты. После рабочей записи
левой предлагай правую, после правой — левую; для выбранной стороны используй
первую свободную цель. При последовательной записи это две стороны одного номера. Ручной
выбор стороны остаётся доступным: запись только левой не требует создавать правую.

Серия миоповторений хранит цель/факт каждого компонента отдельно, включая
изменение веса между подходами. В форме покажи обычную последовательную нумерацию
подходов, у первого — подпись «активация». После неё предлагай повторения и вес
следующей плановой цели. Величину отдыха бери из программы; не навязывай
универсальное значение. Завершение упражнения не создаёт незаписанные факты.
Переход от активации к короткому назначению подтверждён пользователем:
повторения активации не переносятся в следующий подход. Перенос отклонённого
ввода между сторонами и компонентами миосерии исключён;
для обычных подходов прежнее поведение ADR-0019 сохраняется.

Разминка не занимает рабочую позицию, не входит в миогруппу и не определяет
следующий рабочий ввод. Дополнительный рабочий результат сохраняется отдельно
от исходного назначения: выполнение сверх плана не расширяет опубликованную
программу. Для сторон это относится к каждой стороне; для миоповторений
дополнительный подход продолжает ту же серию по последней короткой цели.
Управление несколькими сериями в текущий макет не входит.

## Показатели

Для собственного веса сравнивай повторения, для времени — секунды, для шкалы —
показание и повторения на том же оборудовании. Не показывай для них фиктивный тоннаж.
Для известной внешней массы можно показывать отдельный суммарный внешний объём:
`вес одного снаряда × число снарядов × повторения`; для сторон суммируй уже записанные
компоненты без ещё одного множителя 2. Называй единицы и соглашение явно.
Само число повторений не умножай на число снарядов: одновременное движение двух
гантелей остаётся одним повторением. Если каждая сторона записана отдельно,
суммарные повторения получай сложением её реальных результатов.

Для аналитики различай обычные подходы, результаты сторон и компоненты серии
миоповторений. На экране записи достаточно числа подходов этой серии с отметкой
дополнительных; отдельное управление группами не требуется. Проценты выполнения не означают
качество техники или тренировочный эффект и не включают автоматическую прогрессию.
Прежние серии `per_implement_kg` не пересчитывай молча по новой формуле.

## Совместимость и границы

Введена новая версия общей модели целей/результатов, снимков и операций,
согласованная между сервером, REST/MCP, PWA, историей и аналитикой. Сохрани приём
старых операций v1, их ID, содержание, fingerprints, квитанции и старые снимки.
Из исторического нулевого веса не угадывай собственный вес; из повторений — время.
Старому клиенту, который не умеет показать новую программу, нужен явный путь
обновления без очистки очереди, а не неполная программа или переименование единиц.
Новый REST/MCP-клиент явно передаёт `X-Gym-Schema-Version: 2`. Без него чтение
нового документа возвращает `upgrade_required` целиком, без частичного списка.
Проверка поддерживаемой версии при публикации и записи выполняется внутри
транзакции: отказ старому клиенту не должен скрывать успешную запись.

Реализация охватывает валидацию/одобрение программы, запись и исправления,
офлайн-очередь, смешанную старую/новую историю, показатели и инструкции тренера.
Автоматическая прогрессия, календарный планировщик, таймер с фоновым выполнением,
общие программы и новые права агента в этот объём не входят.

Обязательные проверки: изоляция владельцев; левый/правый факт и повторы
операций без дублей; две гантели против одной на каждую сторону; миогруппа со
сменой веса/пропуском/исправлением; секунды и неизвестная шкала без фиктивных кг;
старые снимки/очередь после обновления; публикация только одобренной редакции.

## Интерфейс: расширение существующего экрана записи

Сохрани порядок текущего экрана: возврат к упражнениям, название/оборудование,
карточка плана, форма нового подхода, список записанных фактов и кнопка
«Завершить упражнение». Последняя возвращает к обзору, допускает неполный план
и не создаёт результатов за пропущенные подходы. Сохрани оформление текущей PWA.

В форме остаются «Рабочий / Разминка», крупные поля с кнопками +/− и основная
кнопка «Записать подход». После записи снова открывай новый рабочий ввод.
Отдельной команды для каждого очередного подхода и перехода на другой экран
не требуется. После исчерпания плана форма остаётся доступной с подписью
«Дополнительный»: можно записать любое фактическое количество. План и его
знаменатель остаются прежними. Стороны, время и миоповторения расширяют эту форму,
а не заменяют её фиксированным набором карточек целей.

Название оборудования и соглашение о весе видны рядом с вводом. Например:
«Общий вес, включая гриф» либо «На одну гантель · одновременно 2».
Смена единиц или соглашения не происходит через переименование подписи:
это новая семантика программы.

| Сценарий | Ввод и действие | Обратная связь |
| --- | --- | --- |
| Упражнение каждой стороной | Л/П внутри основной формы; отдельная запись выбранной стороны | Счётчики сторон и полных пар; другая сторона остаётся незаписанной |
| Собственный вес | Только повторения, подпись «Свой вес» | Плановые и фактические повторения, без нулевого тоннажа |
| Удержание | Поле `мм:сс` и кнопка записи; для бокового — две стороны | Плановая и фактическая длительность; несколько подходов допускаются той же моделью |
| Миоповторения | Та же кнопка записывает активацию и следующие короткие подходы с собственными целями и подсказкой отдыха | Подходы серии нумеруются последовательно; разминка записывается отдельно |
| Неизвестная шкала | Поля «Показание шкалы» и «Повторения» | Нет подписи кг/фунтов и расчёта тоннажа |

После последнего планового короткого подхода следующий рабочий ввод продолжает
ту же серию с последней плановой целью и отметкой «Дополнительный». Отдельной
кнопки добавления мини-подхода нет; новая активация/группа автоматически не
начинается. Факт появляется после обычного действия «Записать подход».
Исходные назначения не изменяются. Связь компонентов серии остаётся частью
внутренней модели, без дополнительного действия пользователя.

Нажатие записанной карточки открывает существующую форму исправления:
«Сохранить изменения», «Удалить подход», «Отмена». Исправление сохраняет тот же
факт и не добавляет подход, сторону или мини-подход. Изменение левой не меняет
правую. Удаление планового рабочего факта освобождает его позицию; удаление
разминки или дополнительного факта не освобождает плановую цель. Следующий новый
ввод использует первую свободную позицию своей стороны/группы; уже начатый
черновик автоматически не перезаполняется. Другие записанные факты не
перенумеровываются и не перепривязываются к новым целям. При этом перенос
последнего отклонения может менять значения ввода, но не исходную цель сравнения.

### Предзаполнение и разминка для новых типов

Для обычного веса и повторений сохрани ADR-0019, включая перенос обоих
отклонённых значений и разминку 70% веса × 1,5 повторений. Вес округляется до
ближайшего грамма, повторения — вверх до целого с пределом 1000.
При весе одного снаряда расчёт применяется к вводимому весу одного; число
одновременно используемых снарядов остаётся свойством упражнения.

В новых вариантах предлагается:

- Перенос отклонения рабочего результата — только в пределах одной стороны и
  обычной последовательности. Для собственного веса переносится число повторений,
  для длительности — время. Между сторонами переноса нет.
- В миогруппе каждый компонент получает собственную цель; автоматического
  переноса отклонения между активацией и мини-подходами либо между разными
  мини-подходами нет. Это расширение ADR-0019 только для новой структуры.
- Разминка со своим весом предлагает 1,5 числа повторений следующего рабочего
  ввода, без поля веса. Это редактируемый шаблон, не рекомендация новой нагрузки.
- Для неизвестной шкалы разминочное показание вводится вручную; нельзя считать
  70% отметки доказанным эквивалентом 70% нагрузки. Повторения — по прежнему правилу.
- Для удержания разминочная длительность вводится вручную; формула повторений
  не переносится автоматически на секунды.

Поля не считаются фактом до записи. Повторное нажатие выбранного типа не сбрасывает
ручной ввод; смена типа новой формы рассчитывает его шаблон, а при исправлении
сохраняет фактические значения. Незавершённый ввод сохраняется при переходе
между упражнениями. Это продолжение принятого поведения ADR-0019.

Локальный макет хранит результаты и черновики только в памяти вкладки;
обновление страницы очищает демонстрационные данные. Он не вызывает API и не
меняет Gym. Переключатель примеров находится вне экрана приложения.

На этом этапе таймер не требуется: пользователь может записать длительность
вручную. В PWA локальное сохранение результата обязательно
до подтверждения в интерфейсе, а доступность сети не определяет успешность записи.

## Представление и переход

`ProgramContentV2` имеет `content_schema_version: 2`. У упражнения отдельно
заданы `measurement`, `load`, `sides`, `set_structure`, `rest_seconds`.
Цель и факт содержат явные nullable-поля `weight_g`, `reps` (для цели —
`suggested_reps`), `scale_milli`, `duration_seconds`; неиспользуемые значения —
`null`. Дробная отметка шкалы передаётся целым числом тысячных, без перевода в массу.
`implement_count: 2` разрешён только для веса одного снаряда.

Снимок получает `snapshot_schema_version: 2` и `fixed-v2`, его операции —
`schema_version: 2`. Снимки и операции v1 остаются v1. Свободная цель определяется
по упражнению, target ID и стороне. Изменение факта не меняет сторону; смена
типа рабочий/разминка пересчитывает привязку, остальные исправления сохраняют её.
Серия миоповторений одна на упражнение и сторону; первый target — активация,
последующие — короткие. Дополнительный факт сравнивается с последней короткой
целью. Отдельные группы/идентификаторы минисетов не нужны для этого объёма.

`stats-v2` разделяет ряды по версии семантики, измерению, нагрузке, числу
снарядов, стороне и структуре. Внешний объём v2 учитывает число снарядов;
исторический объём v1 сохраняется. Сводка показывает рабочие записи, обычные
подходы, результаты сторон, миосерии/их компоненты, повторения и секунды.
Эти счётчики могут пересекаться: компонент миосерии на одну сторону является
также результатом стороны. Они не складываются в число обычных подходов.

Все документы сохраняются в существующих JSON payload YDB; новая DDL-миграция
не требуется. Полные схемы и ограничения находятся в `contracts/schema.json`.
После проверок и merge пользователь проверяет staging. Личные назначения и
учётные данные остаются вне публичного репозитория.
