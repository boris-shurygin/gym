# ADR-0019: Предзаполнение разминки и перенос изменённых рабочих значений

- **Статус:** Принят по запросу пользователя 2026-10-31
- **Дата:** 2026-10-31
- **Заменяет:** пункт 1 ADR-0008 о безусловном плановом предзаполнении
- **Связано:** ADR-0006, ADR-0008, ADR-0015, ADR-0016

## Контекст

Пользователь попросил предзаполнять разминку, например 70% рабочего веса на
полуторное число повторений. Для рабочих подходов нужно продолжать программу,
пока фактические значения ей соответствуют, и повторять внесённое изменение
в следующих подходах. Раньше каждый новый ввод безусловно брал плановую цель.

## Решение

1. При открытии нового рабочего подхода определи его исходную плановую цель
   по прежним правилам. Если последний неудалённый рабочий подход этого упражнения
   в этом занятии отличается от своей сохранённой цели весом или повторениями,
   предзаполни **оба** значения из этого результата. Сравнивай с целью предыдущего
   подхода, а не со следующей: программа может задавать разные назначения.
2. Если последнего рабочего результата нет или он соответствует своей цели,
   используй цель следующей свободной позиции; для дополнительного — последнюю
   плановую цель. Разминка, удалённые результаты и другие упражнения не являются
   основанием переноса. Если повторяемое значение вновь совпало со своей целью,
   следующие назначения снова берутся из программы.
3. Для новой разминки возьми значения следующего рабочего ввода по правилам выше:
   вес × 0,7, повторения × 1,5. Расчёт веса выполняется в целых граммах с округлением
   до ближайшего грамма; повторения округляются вверх до целого с пределом 1000
   по существующему контракту. Нулевой рабочий вес даёт нулевой разминочный.
   Это редактируемый шаблон ввода, а не новая персональная рекомендация программы.
4. Меняется только ввод новой записи. Сам по себе расчёт ничего не сохраняет.
   Исходные цели снимка, привязки рабочих позиций, сравнение планового/фактического
   объёма, число рабочих подходов, программа и серверная прогрессия прежние.
5. Уже записанный подход открывается с его фактическими значениями. Обычное
   обновление данных не заменяет незаписанный черновик. Повторное нажатие выбранного
   типа подхода не сбрасывает ручной ввод. При явной смене типа в **новой** форме
   рассчитываются значения выбранного типа; в форме исправления факт сохраняется.

## Компромиссы и последствия

Перенос последнего отклонения уменьшает повторный ввод в пределах упражнения,
но может продолжить и случайно записанное отклонение. Перед сохранением значения
видны и редактируемы; программа и её исходные цели показываются отдельно.
Специальный флаг «пользователь изменил ввод» в очереди или на сервере не нужен:
правило восстанавливается из сохранённых фактов и их целей после офлайн-перезапуска.

Формула разминки может не совпадать с доступными блинами/делениями тренажёра.
Шаг кнопок не считается каталогом оборудования и не округляет исходные цели;
пользователь может изменить предложенное значение. Исправление последнего
рабочего результата влияет на ещё не начатый ввод, но не переписывает другие факты.

Остальные пункты ADR-0008 сохраняются. Это правило предзаполнения PWA, а не
автоматическая смена нагрузки или публикация программы по ADR-0016.
