# ADR-0020: Проверки по области изменений и завершение проверки выпуска

Статус: Принят по запросу пользователя 2026-10-31.

## Контекст

Полный браузерный набор и несвязанные серверные задания выполнялись для небольшой правки UI. После успешного staging агент повторял уже выполненные deploy-проверки, существенно задерживая ответ. Пользователь попросил оставить необходимые тесты и сократить цикл разработки.

## Решение

Выбирай проверки по Git-диапазону через `scripts/check_scope.py`. Известные компоненты отображения/CSS проверяй сборкой, быстрыми unit и двумя сквозными Chromium-сценариями. Изменения хранилища, синхронизации, авторизации и общих контрактов сохраняют интеграционные проверки; неизвестная область включает полный профиль. Полную матрицу выполняй также ночью и вручную. Убери повтор всех сценариев на desktop Chromium, сохрани мобильные Chromium/WebKit и desktop smoke.

Итоговое CI-задание требует успеха всех выбранных проверок. Release gate получает план из того же успешного push CI, сверяет SHA и не выпускает приложение при изменениях только документации/тестов. Привязка к доверенному main/run/attempt и неизменяемость артефактов ADR-0013 сохраняются.

После успешного deploy один раз сверь публичную идентичность выпуска штатной командой с ограниченным ожиданием. Этого достаточно для обычной UI-полировки: повторную проверку облака/браузера выполняй при конкретной причине, а не как обязательный ритуал.

## Последствия

Обычные правки отображения не требуют API fixture, YDB и полной браузерной матрицы. Список лёгких компонентов должен оставаться явным: `App.tsx` содержит оркестрацию данных и не входит в него. Ночная проверка дополняет, но не заменяет обязательные проверки изменённых модулей. Полный выпуск backend пока остаётся частью публикации UI; дальнейшее ускорение деплоя требует отдельной проработки. Замеры и команды — в [разборе проверок](../testing-review.md).
