# Gym

Многопользовательская система учёта тренировок с двумя взаимодополняющими сценариями:

- **В зале:** удобная для сенсорного управления мобильная PWA для выполнения тренировки, записи подходов за несколько нажатий и просмотра истории и графиков — в том числе без интернета.
- **Вне зала:** ИИ-агент для планирования, интерпретации результатов и изменения тренировочных программ через API/MCP.

**Агент определяет тренировочную стратегию и правила прогрессии**, а **сервер рассчитывает конкретные предписанные нагрузки**. Журнал тренировок хранится отдельно от планов и не переписывается при изменении программы.

**Состояние проекта:** на [staging](https://d5d734k3s76t42pa5rtn.764nr5vy.apigw.yandexcloud.net/) проверены Яндекс ID, закрытый допуск, версии программ и [сервер занятий/квитанций P07](infra/workouts-sync.md) на YDB. [Клиент P08](web/README.md) подключает офлайн-очередь, повторы, кэш и явный разбор конфликтов; [реализация и ограничения](docs/pwa-sync-implementation.md) описаны отдельно. PR #25–#28 слиты; staging 0337dc1…_41099549515_1 установлен. Автоматическая [ротация тегов](infra/function-tag-retention.md) staging/production сохраняет текущую и две предыдущие успешные установки. Точные установленные выпуски и приёмка — в [журнале](docs/development-log.md), команды — в [infra/README.md](infra/README.md).

## Локальный запуск

Для обновления старой установленной PWA и добавления двух шаблонов см. [использование staging](docs/staging-usage.md). Публикацию исправления сверяй с журналом.

В текущем Windows-окружении Node установлен локально, поэтому из корня можно запустить собранный клиент:

```powershell
& ./scripts/web.ps1 -Task build
& ./scripts/web.ps1 -Task preview
```

Открой <http://127.0.0.1:4173/>. Для нового окружения и обычного npm см. [инструкцию клиента](web/README.md); для работы без сети сначала дождись загрузки сборки. Программа синтетическая, записи остаются в этом браузере.

## Следующие шаги

P04/P05 завершены: автоматический staging, защищённый ручной production и восстановление проверены. P06/P07 приняты на staging с OAuth/Lockbox, минимальными правами runtime, одобрением программ, снимками занятий и YDB-квитанциями. P08 установлен, функциональная приёмка подтверждена по слоям; ограничения RU/полного live-browser прогона и проверка физических телефонов записаны в журнале для приёмки перед пилотом. P09 и production требуют следующего запроса. Теги будут сохраняться по политике текущая + две предыдущие успешные установки (ADR-0018), без накопления до квоты. Критерии — в [плане](docs/development-plan.md), фактические проверки — в [журнале](docs/development-log.md).

Для работы используй фразы «Продолжаем разработку», «Завершаем этап», «Мержим ПР», «Деплой на стейбл» или навыки `$gym-next-stage`, `$gym-finish-stage`, `$gym-merge-pr`, `$gym-deploy-stable`. Престейбл — staging, стейбл — production.

Для полного цикла без промежуточных подтверждений используй «Сделай P05 полностью», «Дальше автономно» или «Выполни P05–P07 полностью». [Автономный режим](docs/development-workflow.md#автономный-режим) включает реализацию, PR, ожидание CI, merge и проверку staging в пределах указанного объёма; выпуск в production требует явного разрешения.
