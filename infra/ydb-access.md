## План, применение и проверка

Используй зависимости [db/requirements.txt](../db/requirements.txt) и свою локальную авторизацию YC. Запускай из корня репозитория; в Linux укажи `--yc` с путём к YC CLI. Токены оператора/сервисных аккаунтов захватываются только в память через `yc iam create-token`; постоянные ключи не создаются.

```powershell
# Только чтение: показывает недостающие IAM/ACL, не меняет облако.
& ./.local/backend-venv/Scripts/python.exe -X utf8 -m infra.ydb_access

# После согласия на описанный план:
& ./.local/backend-venv/Scripts/python.exe -X utf8 -m infra.ydb_access --apply
& ./.local/backend-venv/Scripts/python.exe -X utf8 -m infra.ydb_access
& ./.local/backend-venv/Scripts/python.exe -X utf8 scripts/verify_ydb_access.py
```

План проверяет ID/каталог/имена ресурсов, метку базы, прямые роли целевых аккаунтов и публичные назначения на базе и родительских каталогах/облаке/организации. Обходит пользовательские схемные объекты и обнаруживает прямые ACL API вне allowlist, дополнительные права, владение объектом и отключённое наследование. При расхождении останавливается **до первой мутации**, не удаляет существующие назначения и не расширяет их молча. Повтор после успешного применения должен показать пустые `iam` и `acl`; несколько IAM/ACL-запросов не являются общей транзакцией, частичный сбой исправляется повтором после проверки плана.

Проверка создаёт собственные случайные синтетические таблицы: прикладную и административную. Мигратор создаёт/изменяет схему и выдаёт API DML только на прикладную. API выполняет запись, исправление, чтение и удаление с проверкой результата; CREATE/ALTER/DROP/GRANT и чтение/запись административной таблицы должны получить отказ. Три CI-личности не должны выполнить DML/DDL; у личности без доступа к подключению отказ возможен уже при создании сессии. Сетевой сбой, timeout, синтаксическая ошибка или недоступность не считаются успешным отказом. Для закреплённого SDK учитывается точный gRPC `PERMISSION_DENIED`, который он оборачивает в `ConnectionLost`. YDB также возвращает запрет разрешения таблицы как `Aborted`: принимается только структурированный issue 2028 с явным `status: AccessDenied`, в том числе вложенный; обычный abort/conflict не считается отказом доступа.

Каждая тестовая сессия/RPC ограничена временем, фоновых бесконечных повторов нет. Для каждой отрицательной CI-пробы создаётся независимый драйвер: SDK отключает канал после gRPC-отказа, поэтому повторное использование такого канала не доказывает запрет следующей операции. В `finally` оператор удаляет только проверенные случайные имена этого запуска, включая неожиданно созданную API таблицу, и повторно проверяет отсутствие расхождений ACL. При недоступности облака очистка может не завершиться: сообщение об ошибке не означает, что ресурсы удалены; проверь собственные имена перед ручной очисткой. Сценарии отказываются работать в GitHub Actions. Unit-тесты запускаются в обычном API job без токенов и облачных прав.

Прогон 2026-10-27 завершил все 19 групп проверок. API получил `UNAUTHORIZED` на CREATE/ALTER/DROP/GRANT и `Aborted` с resolve `AccessDenied` на DML административной таблицы. Staging CI получил такой же запрет данных и `UNAUTHORIZED` на DDL; CI из delivery/production — gRPC `PERMISSION_DENIED` уже на сессии. После очистки независимая проверка SQLAlchemy показала 0 таблиц. Проверены именно временные IAM-токены сервисных аккаунтов: подключение развёрнутой функции/контейнера через metadata ещё предстоит.

## Границы и восстановление

План не доказывает отсутствие любых возможных групповых доступов: перед допуском проверяются фактические действия под временными токенами нужных личностей. Новые IAM/групповые назначения могут изменить эффективные права — повторяй отрицательные проверки после изменений доступа. Production здесь не изменяется и не проверяется.

Отзыв выполняет оператор: удали два назначения `ydb.auditor` **на этой базе**, отзови перечисленные восемь ACL у `ajedn74q9psjfecqnteg@as` в корне, а также ранее выданные API разрешения на явных таблицах. Отзыв корневого ACL не отменяет владение таблицами, созданными мигратором: при полном выводе личности из эксплуатации отдельно передай владение и проверь дочерние ACL. Не удаляй таблицы или другие назначения ради отката прав. Образ, приватный контейнер, получение metadata credentials из runtime и восстановление job/lock — следующий P04.2.2, не результат этого инструмента.
