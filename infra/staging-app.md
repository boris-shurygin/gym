# Выкатка API/PWA/Gateway на staging (P04.3.2.2)

После успешного `migrations` новый job `deploy` проверяет тот же опубликованный выпуск и фактический статус миграций, создаёт/переиспользует приватную версию API по уникальному тегу, загружает готовые PWA-байты и последним переключает Gateway. Smoke проверяет HTTPS, хеши файлов/заголовки, health, закрытые личные маршруты и приватность backend. Production не запускается.

Editor включает удаление целевой функции/шлюза; код удаления не выполняет. ActAs разрешает запуск кода под этими SA; проверенный main остаётся границей доверия. CI не получает прямых новых YDB-прав. У бакетов/функции не появляется анонимного доступа: публичен HTTPS Gateway, который отдаёт только PWA и HTTP API с прикладной проверкой доступа. Служебные deployment receipts не доступны SA Gateway. Права production не меняются.

Политика сохраняет контроль оператора, запрещает CI перезапись без If-None-Match: *, удаление и изменение ACL/политики. Неизвестные политики, публичные ACL и лишние роли останавливают применение. IAM из workflow не меняется.

## Состав выпуска и порядок

`gateway.json` нового выпуска — нейтральный OpenAPI-шаблон версии `release-template-v1`; рендерер допускает только этот известный формат. Он подставляет фиксированные ID staging, уникальный API-тег и release-префикс. API/PWA не пересобираются на deploy. Хешированные assets сохраняются общими неизменяемыми ключами, поэтому старый HTML продолжает загружать свои JS/CSS. Index/manifest/service-worker/icon читаются из префикса выбранного выпуска; указатель Gateway переключается после загрузки всего набора. Успешный receipt записывается только после smoke.

До merge оператор проверяет опубликованные API/PWA прежнего main и новый рендерер только в staging с `--validation-gateway`: допускается точный SHA-256 прежнего bootstrap-шаблона, применяется новый локальный формат и отдельный validation-тег API. Такой запуск помечается `operator-validation`; он не является кандидатом production и не подменяет манифест выпуска. В CI этот режим запрещён. После merge проверяется обычная автоматическая выкатка нового выпуска с новым gateway artifact.

При ошибке миграций не создаются версии/файлы приложения. При ошибке подготовки API/статики Gateway не переключается. Ошибка smoke не создаёт успешный receipt; повтор сначала читает реальное состояние, одинаковые версии/объекты переиспользуются. Автоматического отката схемы, удаления старых ресурсов или production-promotion нет.
