## Конфигурация и запуск

В [bootstrap.json](bootstrap.json) хранятся облако, аккаунты, федерация и бюджет, в [resources.json](resources.json) — параметры пустых ресурсов. Это несекретные настройки. Сценарии сначала читают фактическое состояние и проверяют границы; без `-Apply`/`--apply` показывают план. Они создают отсутствующие ресурсы, но не выполняют произвольное обновление или удаление. При обнаружении чужого владельца, публичного бакета или других лимитов остановись и разбери расхождение.

Используй PowerShell 5.1+ или PowerShell 7 и Python 3.12+. Установленный локально официальный YC CLI 1.41.0 находится в `.local/bin/yc.exe`; каталог исключён из Git. На Linux передай путь к установленному `yc` параметром `-YcPath` или `--yc`. Скачанный Windows-файл имеет SHA-256 `637BE6251F3178FC55D3771258C791849F5E486EAA81F6A04A70EC9DD5ACF6DC`.

При новой настройке авторизуйся самостоятельно через `yc init`, выбери указанное облако. Используй существующую авторизацию GitHub с административными правами репозитория: сценарий берёт её из `GH_TOKEN` либо Git credential helper. Не копируй конфигурацию CLI, токены или ключи в репозиторий/чат. Первоначальная настройка требует прав оператора; учётные данные оператора в CI не передаются.

Из корня репозитория проверь план:

```powershell
& ./infra/Bootstrap-Cloud.ps1
& ./infra/Configure-GitHub.ps1
& ./infra/Provision-Resources.ps1
py -3.12 infra/configure_budget.py
```

На чистой машине сначала выполни `Bootstrap-Cloud.ps1 -Apply`: он создаёт `.local/bootstrap-state.json`, необходимый следующим сценариям. Файл содержит только обнаруженные ID и не является заменой чтению состояния облака. Применяй проверенный план:

```powershell
& ./infra/Bootstrap-Cloud.ps1 -Apply
& ./infra/Configure-GitHub.ps1 -Apply
& ./infra/Provision-Resources.ps1 -Apply
py -3.12 infra/configure_budget.py --apply
```

Если Windows запрещает запуск локальных сценариев и нет обязательной политики организации, разреши их только текущему процессу: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`. Не меняй машинные политики. `Provision-Resources.ps1` сохраняет обнаруженные ресурсы в игнорируемом `.local/resources-state.json`. После прерывания снова просмотри план: уже созданные объекты будут найдены, удаления и повторы баз не нужны.

Суффикс публикации — `:ref:refs/heads/main`, окружений — `:environment:staging` и `:environment:production`. При переносе репозитория или смене шаблона subject сначала проверь фактические настройки GitHub и пересмотри конфигурацию доверия.

Окружения GitHub `staging`/`production` допускают только ветку main, без тегов. Production требует одобрения владельца; self-review разрешён для единственного владельца, обход администратора запрещён. В окружениях сохранены только несекретные Variables: `YC_CLOUD_ID`, `YC_FOLDER_ID`, `YC_OTHER_FOLDER_ID`, `YC_SERVICE_ACCOUNT_ID`, `YC_FEDERATION_ID`, `YC_OIDC_AUDIENCE`, `GYM_ENVIRONMENT`, `GYM_MONTHLY_BUDGET_RUB`. Постоянные облачные ключи в GitHub не создавались.

[Cloud access](../.github/workflows/cloud-access.yml) запускает тесты на PR без OIDC. После попадания в main push проверит OIDC для staging, ручной запуск позволяет выбрать production и проходит его gate. Проверка обменивает JWT на короткий IAM-токен, читает метаданные своего каталога и требует отказа для другого окружения. Токены остаются в памяти; вывод содержит только результат. До merge настоящего запуска на GitHub ещё нет. Это проверка доступа, приложение она не развёртывает. Защиту main обязательными checks настрой после появления первого успешного запуска, чтобы не потребовать несуществующий check.

## Расходы

Пользователь разрешил до **3 000 ₽ в месяц** на инфраструктуру Gym. Обе YDB — Serverless в `ru-central1`, без зарезервированных RU, с включённым ограничением 10 RU/с, хранением до 1 GiB и защитой от удаления. Каждый бакет ограничен 1 GiB; анонимные чтение, листинг и конфигурация запрещены. Функции/контейнеры ещё не имеют исполняемых версий, у шлюзов отключена запись журналов. Лимиты для будущих версий и журналов задавай при реализации выпуска.

[configure_budget.py](configure_budget.py) создаёт бюджет `gym-monthly-3000-rub`: месячная стоимость до скидок, только три каталога Gym, уведомления оператору первоначальной настройки на 80%, 95% и 100%. Срок действия — до 2027-10-31; продли его заранее через согласованное изменение конфигурации. Другие бюджеты не изменяются. [Бюджетные уведомления YC](https://yandex.cloud/ru/docs/billing/operations/budgets) сообщают о порогах; автоматической остановки всех расходов здесь нет.

Числовая переменная GitHub сама по себе ничего не ограничивает. Контролируй фактические расходы, включая трафик, запросы Gateway, хранение Registry/резервных копий и будущую диагностику. Не обещай соблюдение денежного потолка только на основании RU/размера бакетов. При превышении прогноза сначала разберись с источником, не удаляй production автоматически.

## Проверки

```powershell
py -3.12 -m unittest discover -s tests/infra -p 'test_*.py' -v
git diff --check
```

На Linux используй `python3` вместо `py -3.12`. PowerShell-тесты требуют `pwsh`; если он отсутствует, эти тесты пропускаются, что не равно полной проверке. GitHub workflow использует образ Ubuntu с PowerShell.

Локальные тесты не обращаются к облаку: проверяют план, повторное применение, границы владельца, дрейф публичности/лимитов, доверие OIDC и бюджет. В живом облаке отдельно подтверждены повторный план без изменений, закрытые бакеты, YDB RUNNING с лимитами, отсутствие исполняемых версий и ответы шлюзов 503. Реальные OIDC/отрицательные проверки CI, права на таблицы, миграции, автоматический выпуск и восстановление остаются работой следующих этапов.
