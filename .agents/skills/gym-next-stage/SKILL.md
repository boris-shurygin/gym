# Начать или продолжить этап Gym

Прочитай [процесс разработки](../../../docs/development-workflow.md), затем README, применимые AGENTS.md, [план](../../../docs/development-plan.md) и [текущий журнал](../../../docs/development-log.md). Прочитай индекс ADR и относящиеся к этапу решения/спецификации; для инфраструктуры также CI/CD.

1. Проверь рабочее дерево, ветку, remote и изменения origin/main. Сохрани исходные правки пользователя. Не утверждай, что main актуален, если получить его не удалось.
2. Определи режим и объём из запроса и ранее записанного разрешения. «Полностью», «под ключ», «автономно» для этапа/диапазона разрешают полный цикл по [правилам автономного режима](../../../docs/development-workflow.md#автономный-режим). Без ID в таком запросе выбери текущий незавершённый крупный этап Pxx либо первый доступный крупный этап со всеми подпунктами. Обычную команду без ранее данного разрешения выполняй до проверки результата пользователем.
3. Продолжи незавершённую работу, сверяя план/журнал с GitHub. Для «PR открыт» сначала проверь ревью/CI; в автономном режиме доведи этот PR до разрешённого merge/staging. Если этап уже слит, проверь его критерии и staging до перехода к следующему разрешённому этапу. При недоступном GitHub продолжай независимую подготовку с явным ограничением, не выдумывая фактов merge или успешного CI.
4. Сообщи выбранные ID, границы и критерий окончания без запроса повторного подтверждения. Для новой части используй ветку от актуального main; при продолжении сохрани существующую работу. Организуй задачи, коммиты и небольшие PR самостоятельно; создавать формальные подпункты плана не обязательно. Обычные технические решения принимай сам, блокирующие продуктовые/архитектурные выборы обсуди, продолжая независимую работу.
5. Обновляй план и журнал: режим, разрешённый объём, состояние, базовый SHA, ветка/PR, результат, реальные проверки, блокеры и точка продолжения. Сохраняй разрешение при продолжении работы и восстановлении контекста; не расширяй его на весь оставшийся план.
6. В обычном режиме переведи результат в «На проверке» и заверши краткой сводкой изменений, проверок и ограничений. В автономном режиме последовательно используй [gym-finish-stage](../gym-finish-stage/SKILL.md) и [gym-merge-pr](../gym-merge-pr/SKILL.md): подготовь PR, дождись CI, исправь ошибки, смержи проверенный head, обнови main и проверь staging. После успеха продолжи следующий этап только внутри разрешённого списка/диапазона. Информационные сводки и промежуточные PR не требуют ответа пользователя.

Остановись после согласованного объёма, по явной просьбе пользователя или при конкретном блокере, который нельзя устранить в разрешённых границах. При сбое сначала проверь логи и фактическое состояние; не повторяй миграции вслепую и не запускай бесконечные повторы CI. Границы допусков, повторов и обращения к пользователю определены в процессе разработки.

Production выполняй только при явном разрешении на выпуск, в том числе данном в исходном запросе; тогда используй [gym-deploy-stable](../gym-deploy-stable/SKILL.md). Подготовка production workflow сама по себе не разрешает выпуск. В конце автономной работы сообщи выполненный объём, PR/merge, проверки, фактический staging-выпуск и оставшиеся ограничения.
